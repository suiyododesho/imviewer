# 実装要件ファイル

## このファイルについて

このファイルは、imviewerの機能追加や改善要件、バグ・不具合修正の内容を記録するためのものです。実装に必要な情報を整理し、開発者が効率的に作業できるようにすることを目的としています。

要件には管理番号を付与し、見出しの形式で記載してください。管理番号は、機能追加要件には「F」、改善要件には「M」、バグ・不具合修正には「B」を接頭して付与してください。例：F01、M02、B03など。

対応終了した要件については、見出しの冒頭に【対応済】を付けてください。その他、ステータス定義と語句の関係は以下の通りです。

- 【予定】：今後実装予定の要件
- 【対応中】：現在実装作業が進行中の要件
- 【対応済】：実装が完了し、リリースされた要件
- 【保留】：実装の優先度が低い、または要件の内容が不明確なため、現時点では対応しない要件

## 機能追加(Functionality)

### 【予定】F01:タグ絞り込み機能（シリーズ）

シリーズで定義済のタグを、タグ絞り込み機能で選択できるようにする。

- シリーズ表示カードにタグを並べて表示する。
- シリーズ内のコンテンツ一覧画面にもタグを表示する。場所はコンテンツのカード表示領域（リストモード時はリストのカード表示領域）の先頭。
- タグをクリックすると、そのタグを持つシリーズのカードだけが表示されるようにする。

### 【予定】F02:タグ一覧表示画面の追加

タグ一覧表示画面を追加する。

- タグ一覧表示画面を追加する。場所はサイドバーの新セクションに「タグ一覧」を追加する。
- タグ一覧表示画面では、タグの名前と、そのタグを持つシリーズの数を表示する。
- タグをクリックすると、そのタグを持つシリーズのカードだけが表示されるようにする。

### 【予定】F03:toolにて、アップデート作業を実行するツールを追加する

toolにて、アップデート作業を実行するツールを追加する。githubのmainブランチのソースコードを使用する。zipファイルをダウンロードして展開する方法でOK。展開後のファイルを、運用中のwebシステムの環境上で実行したときに、上書きコピーする。

注意点として、メンテナンスツールで自動生成・自動更新されるファイルは、上書きコピーの対象から外すこと。これらのファイルは、運用中のwebシステムの環境上で実行したときに、自動生成・自動更新されるため。（例：gallery-pages.js、structure.json、structure.jsなど）

システムを運用するディレクトリでは`.git`が存在しないため、gitコマンドを使用してのアップデートはできない。zipファイルをダウンロードして展開する方法でOK。zipファイルのダウンロードURLは、`maintenance_config.json`のパラメータで定義できるようにすること。システム運用ディレクトリでダウンロード先がわからないため。

### 【予定】F04:toolにて、コンテンツ追加作業をローカルマシンで実行し、サーバーにアップロードするツールを追加する

toolにて、コンテンツ追加作業をローカルマシンで実行し、サーバーにアップロードするツールを追加する。現在の運用ではサーバマシンのストレージをマウントして直接コンテンツ追加作業を行っているが、速度が遅いことが課題となっている。ローカルマシンでコンテンツ追加作業を実行し、サーバーにアップロードする方法であれば、ローカルマシンの高速なストレージを使用できるため、速度の改善が期待できる。

本ツールのディレクトリ構成イメージ

```
tool/   # この環境のtoolディレクトリ
├── content_add/    # コンテンツ追加ツールのディレクトリ
│   ├──workspace/   # コンテンツ追加のワークスペース（※）
│   │   ├── content_add.bat  # コンテンツ追加ツールのスクリプトファイル
│   │   ├── contents/         # 追加対象のコンテンツディレクトリ（運用先のsite/contentsの構造と同一にする）
├── maint_*.py      # maint_*.pyは、この環境で実装済みのmaintenanceツールのスクリプトファイル
├── maintenance_config.json
```

#### （※）コンテンツ追加ツールのworkspaceディレクトリについて

workspaceディレクトリは、コンテンツ追加作業を実行するためのワークスペースである。
本プロジェクトを利用して運用するシステムが複数あり、そのシステムごとにコンテンツ追加作業をできるようにするため。本プロジェクトでは`content_add`というディレクトリ名でツールを開発し、実際に利用するときは`workspace`を複製＆名前変更して使用するイメージ。

当然、複製して使用するディレクトリはgit管理の対象外とする必要があるため、複製して使用するディレクトリ空間には`.gitignore`に追加すること。ディレクトリ名が任意であるため、`.gitignore`には、`tool/content_add/*/`のように、ツールディレクトリ配下の任意のディレクトリをgit管理の対象外とする記述を追加すること。

追加処理は既存のmaintenanceツールの処理を流用する。したがって、`contents`ディレクトリは運用中のwebシステムの`site/contents`の構造と同一にする必要がある。追加処理の実装にあたっては、既存のmaintenanceツールの処理を参考にしつつ、必要な部分を改修して実装すること。コードクローンを行わないようにする。

## 改善要件(Modification)

### 【予定】M01:ギャラリー画面にて、コンテンツ間のページ遷移を追加する

ギャラリー画面にて、コンテンツ間のページ遷移を追加する。

- そのコンテンツのページ先頭を表示中に「prev」操作を実行すると、前のコンテンツのページ末尾を表示する。
- そのコンテンツのページ末尾を表示中に「next」操作を実行すると、次のコンテンツのページ先頭を表示する。

### 【予定】M02:ギャラリー画面にて、通常表示＆拡大率100%の状態では、画像表示領域を上下スワイプしてもページ全体をスクロールさせるようにする

ギャラリー画面にて、通常表示＆拡大率100%の状態では、画像表示領域を上下スワイプしてもページ全体をスクロールさせるようにする。要件記載時点では拡大時の画像表示領域移動の操作が優先されるため、ページ全体のスクロールができない。この問題を解消する。

左右端はページ移動のタップ領域があるため、ここはタップ操作を優先してOK。その他の何も操作がない領域は、通常表示＆拡大率100%の状態ではページ全体のスクロールを優先する。拡大率が100%以外の状態では、画像表示領域の移動を優先する。

### 【予定】M03:toolにて、maintenanceツール内の画像抽出処理の抽出画像サイズを、縦2000pxに変更する

要件記載時点では、maintenanceツール内の画像抽出処理の抽出画像サイズは、長辺2000pxである。これを縦2000pxに変更する。理由は、見開き1枚の画像の単位でページを構成していた場合、単一ページの画像単位と比較して解像度が落ちてしまうため。

また、この画像サイズはtools/maintenance_config.jsonのパラメータで変更できるようにすること。将来的に、ユーザーがこの画像サイズを変更できるようにするため。

### 【予定】M04:toolにて、maintenanceツール内のincremental update処理時に進捗表示を追加する

要件記載時点では、maintenanceツール内のincremental update処理は、処理中に進捗表示がない。これを追加する。理由は、処理時間が長い場合に、ユーザーが処理が進んでいるかどうかを確認できるようにするため。
